# 墨流交互重构：从“高级表单”到“一次触碰”

日期：2026-07-30

## 1. 用户反馈（本轮约束）

- 当前版本视觉有吸引力，但不像 APP，也不像软件。
- 开始一次记录前要填写、判断、选择和阅读，操作负担过高。
- 主交互不够稳定，副交互与主交互争夺注意力。
- 本轮不能只换皮；必须先研究跨赛道优秀产品，再重构交互骨架。

## 2. 参考产品与可迁移机制

### 同赛道

1. **Forest**：用单一可见对象承载专注状态；借鉴“状态一眼可见”，不复制种树与失败惩罚。
2. **Opal**：进行中的 Session 被置于视觉中心；但开始前的时长、阻止列表与难度配置正是墨流要避免的摩擦。
   - https://opalapp.com/screentime
3. **one sec**：同一个短介入动作被反复使用，用户无需学习复杂流程；迁移为墨流的“回来脉冲”。
   - https://one-sec.app/
4. **Endel**：用户选择一个模式后，系统在后台持续适配，参数不占据主界面；迁移为“建议只在需要时浮现”。
   - https://endel.zendesk.com/hc/en-us/articles/360011795480-What-is-Endel

### 跨赛道

5. **Oura**：Today 首先给出此刻最重要的信息，其余记录沿时间线自然展开；迁移为“此刻在上、今日轨迹在后”。
   - https://ouraring.com/blog/da/new-oura-app-experience/
6. **Flighty**：把当前状态放在一个可持续更新的主表面，次要信息按时间与紧急程度出现；迁移为“进行中状态固定占据首屏”。
   - https://developer.apple.com/news/?id=970ncww4
7. **Things 3**：Today 是一个清晰、安静的聚合面；高级功能存在，但不妨碍完成最常见动作。
   - https://culturedcode.com/things/features/
8. **iA Writer**：Focus Mode 让当前一句成为唯一高对比对象，其他内容主动后退；迁移为“进行中只突出当前意图与回来动作”。
   - https://ia.net/writer/
9. **Sunsama**：引导式规划适合每天一次的仪式，不适合每次即时记录；因此墨流不再把引导流程放在每次开始前。
   - https://help.sunsama.com/docs/usage-guides/daily-planning/
10. **Day One**：记录入口必须随手可达，深度整理发生在记录之后；迁移为“先留下，再理解”。
    - https://dayoneapp.com/

## 3. 结论

### 主交互

墨流只有一个需要形成肌肉记忆的动作：

> 开始之后，意识到自己刚才散开时，点一下“我回来了”。

这一次点击自动留下一个“散开 → 回来”的注意力脉冲。用户无需先判断它属于走神、恢复还是失败。

### 副交互

- “被打断”“留个念头”“缓一下”固定在低对比动作带中，一次点击完成，不弹出配置表单。
- “收好这一段”位于进行中状态的右上角，一次点击立即结束，默认记为“推进了一点”。
- 能量、时长边界、结果分类、结束备注全部退出主流程。
- 建议不在开始前教育用户，只在事件发生后短暂出现，不要求回应。
- 设置与账号进入独立抽屉，不占用主导航位置。

## 4. 新信息架构

1. **此刻**：唯一行动面；一键开始，进行中一键回来。
2. **轨迹**：Oura 式今日时间线，查看而非操作。
3. **洞察**：有足够数据才给一条有依据的建议。
4. **设置抽屉**：同步、导出、隐私与删除。

## 5. 首次使用标准

- 不输入文字也能开始，默认意图为“留在此刻”。
- 首次进入只有一个高对比主按钮。
- 从打开应用到开始记录：1 次点击。
- 进行中记录一次走神与回来：1 次点击。
- 结束：1 次点击。
- 任何高级选项都不能挡住上述三个动作。

## 6. 视觉方向

保留用户认可的纸墨、深苔绿与陶土色，但从“编辑型网页”改为“原生注意力仪器”：

- 单一有边界的 APP 壳层，而不是网站式侧栏与大段标题。
- 中央“墨脉冲”是唯一视觉焦点，也是主按钮。
- 底部固定导航与上下文动作带提供软件感。
- 动效只表达状态变化：开始、回来脉冲、记录落点、结束收束。
- 桌面与移动端保持同一交互模型，不分别发明两套流程。
