# 墨流 0.3｜从“计时工具”重做为日常注意力记录

## 这次只解决什么

用户已经明确否定了“打开一个高级计时器”的价值。真正需要的是：在一天正在发生时，能用很低的成本记下注意力放在哪里、什么时候散开、如何回来，并在当下得到一条有用的帮助；一天结束后，不靠记忆也能看见自己的真实状态。

## 用户原始需要与产品回应

| 用户已经明确表达 | 产品必须做出的回应 |
| --- | --- |
| “我不会用” | 首屏只要求写一句“我现在要做什么”；其余信息都有默认值，不先讲产品概念。 |
| “只是一个定时软件” | 计时降为可选附属能力，默认是正计时记录；产品中心是当下记录与注意力事件。 |
| “真正能够帮助到我” | 每个建议必须来自当前状态或已有记录，并且能立刻执行，不展示泛泛的效率金句。 |
| “日常可以实时记录” | 活动进行中可一击记录走神、打断、念头和恢复；当天形成连续时间线。 |
| “UI 界面要求很高” | 使用一套温暖纸张与活墨流线的编辑式界面；动效表达注意力流动，不作装饰性堆叠。 |

## 新的最小闭环

1. **记录此刻**：写一句当前意图，选择大脑状态；时间目标可留空。
2. **正在发生**：应用正计时，但视觉中心是当前意图；用户可随时记下走神、打断、念头或进入短恢复。
3. **被接住**：每次事件之后，界面只给一条基于当前记录的下一步建议。
4. **结束这一段**：用十秒标记完成、推进或暂停，并给未来的自己留一句话。
5. **看见今天**：当天时间线呈现每一段意图、事件与回来，不用把“专注分钟”当成绩。
6. **逐渐认识自己**：数据足够后再显示时段、打断和恢复模式；没有证据时明确说“还不了解你”。

## 第一版信息架构

- **此刻**：开始/继续当前记录、即时事件、短恢复、结束。
- **今天**：当天注意力流、记录列表、简短日结。
- **规律**：近七天有证据的模式与下一条建议；数据不足时诚实等待。
- **设置**：账户/同步状态、提醒偏好、数据导出与隐私说明。

## 数据原则

- 用户的日常记录属于正式产品数据，使用 D1 持久化；浏览器只承担离线草稿和即时恢复缓存。
- 所有写入按已认证用户隔离；本地开发使用明确的 preview 身份。
- 不读取其他应用、浏览历史、Prompt 或屏幕内容；事件只由用户主动记录。
- 建议是透明的行为规则与个人记录汇总，不冒充心理诊断或大模型洞察。

## 本轮明确不做

- 不把倒计时、番茄、连续签到、等级、排行榜重新放回中心。
- 不要求用户先理解“Return Gate”、八状态机或注意力理论。
- 不自动判断用户是否分心，不用页面隐藏事件假装知道用户去了哪里。
- 不在数据不足时伪造“最佳专注时段”。
- 不扩成待办系统、日历系统或聊天式 AI 教练。

## 验收问题

一个从未见过墨流的人，能否在十秒内完成第一条记录？

一次真实走神或打断发生时，能否在不终止当前事情的情况下用一击留下事实？

结束后，用户能否看懂今天的注意力去了哪里，并得到一条有证据、可执行的建议？

如果这三个问题有一个答案是否定的，本轮重做就还没有完成。
