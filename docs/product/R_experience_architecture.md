# R — 信息架构与体验重做

## 信息架构：不是页面树，而是状态轨道

```text
墨流
├─ 当前回流（唯一主界面）
│  ├─ 去向 / intention
│  ├─ checkpoint / next action
│  ├─ 间隙 / waiting or recovery
│  └─ 接回 / return
├─ 最近节律（轻反馈，默认折叠）
└─ 控制（提醒、低能量、清空本机数据）
```

无独立“统计首页、声景页、建议页、历史页”。旧功能不以导航项保留。

## 核心旅程

```text
发出 Agent 任务
  -> 打开/唤起墨流
  -> 选 AI 工作（默认）
  -> 写目的 + 回来第一步
  -> 选择手动或明确模拟
  -> checkpoint 压成断开的轨道
  -> 留白 / 单一微行动
  -> 完成或失败信号
  -> checkpoint 从另一端返回
  -> 用户按“接回这一步”
  -> 自评上下文完整/部分/没回来
  -> 墨流退场，回到真实任务
```

## 关键界面 / 浮层

### Idle / 空状态

- 一句话：“AI 在生成时，先留下回来后的第一步。”
- 一个主按钮：“开始一次回流”。
- 若有未闭 session，只显示“继续这一步”，新建为次按钮。
- 不播放 12 秒开场，不展示统计。

### Intention / 封存台

- 模式作为语义切换：AI、工作、阅读、冥想；不改变内核。
- 两个字段：`你现在要完成什么`、`回来第一步`。
- AI 模式选择“手动完成”或“20 秒/5 分钟模拟”；模拟有常驻标签。
- Enter 提交；目标 2–8 秒完成熟练路径。

### Waiting / 间隙

- 中央是被断开的水平轨道，左端是已封存的 checkpoint，右端留空。
- 主区域不显示大倒计时；小字可显示已等待时长与模拟剩余。
- 只有四个动作：留白、远眺、伸展、整理下一条 Prompt；一次只展示一个说明。
- “任务完成 / 任务失败 / 提前回来”始终可达。

### Recovery / 微行动

- 一屏一个动作，非课程、非循环 feed。
- 留白时隐藏说明，只保留退出与完成信号。
- 低能量模式默认“留白”并减少动效。

### AI 完成 / Return

- 先显示来源：手动、模拟或未来已连接 adapter。
- checkpoint 从断线右端滑回；下一步成为唯一主标题。
- 主按钮：“接回这一步”；次按钮：“目的变了”。
- “目的变了”进入 reroute，不评价失败。

### Review

- 一题：“上下文回来了吗？”完整 / 一部分 / 没回来 / 跳过。
- 一条事实反馈：如“这次完成提示后 18 秒接回”。
- 主按钮：“回到真实任务”，不诱导继续浏览墨流。

## 页面切走、拿手机与通知

- `visibilitychange` 只记录本页可见性，界面文案是“墨流页面曾离开视线”，绝不说“检测到你刷了抖音”。
- 页面再次可见时：若任务已完成，直接进入 Return；若仍 Waiting，只恢复原间隙。
- 浏览器通知为可选增强：首次完成 session 后再解释并请求，不在首屏弹权限。
- 用户拒绝后不重复请求；用不含工作正文的标题 `任务有结果 · 墨流接回` 与页面内 Return Gate 降级。
- 手机端采用底部伴随栏、单列创建与压缩轨道：突出“接回 / 提前回来 / 留白”，不是桌面卡片的等比缩小。

## 低保真选择

1. **状态轨道（选中）**：一条线随状态断开/合流；信息少、机制可见。
2. 双栏交接：左“过去的我”、右“回来的我”；理解直观但移动端割裂。
3. 环形门：中心穿越完成回流；容易重新联想到计时圆环，淘汰。

## 高保真方向

- 深石墨底、骨白文字、唯一信号色“回流橙”；不使用 AI 紫蓝渐变。
- 工程编辑器式精确排版，但避免终端 cosplay；展示可信状态与时间戳。
- 一条“断线合流”是唯一 signature move，所有卡片和装饰让位给它。
- 桌面为低而宽的伴随台；移动端把左轨变成底部伴随栏、内容转单列并缩短轨道，不等比缩放桌面布局。
