## 主机制：Return Packet 回流包

Return Packet 不是一张卡片，也不是任务详情。它是中断前后的一次双向动作：

1. 离开前，用户把“回来后的第一步”压成一行；
2. 回来时，系统先把这一行还给用户；
3. 用户一击接回，完成第一动作后确认上下文是否恢复。

checkpoint 是封存，return handshake 是取回；两者缺一都不能构成连续性。

> **墨流最小不可删除动作是什么？**
>
> **把回来后的第一步封存，再把它一击接回。**

删除计时、声景、统计、账号、动画、AI 文案之后，只要这个动作仍在，墨流就成立。反之，保留全部旧功能但删除它，墨流就退回普通专注工具。

## Signature interaction：断线合流

用户按“封存并离开”时，当前意图压缩成一条有断点的轨道；等待期间中段留白；完成/回流时，checkpoint 从另一端滑回，用户按“接回这一步”后两端合成连续实线。动效只表达状态：连续 → 封存 → 间隙 → 重连，不代表墨水装饰。

## 产品边界

- 系统不替用户写 checkpoint；可提供句式，但内容由用户确认。
- 系统不把 notification delivered 当作回流。
- 系统不判断用户“自律”；只记录状态事件。
- 系统不要求每个间隙做练习；留白是一等选项。
- 系统不保存代码、Prompt 或 Agent 输出正文。
