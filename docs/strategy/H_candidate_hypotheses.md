# H — 候选假设验证表

| 假设 | 支持证据 | 反对证据 | 可证伪条件 | 最小实验 |
|---|---|---|---|---|
| 注意力连续性引擎 | 中断研究显示上下文衰减、恢复延迟与错误；空管/分布式系统依靠状态封存与显式恢复 | “引擎”抽象，用户不会为概念付费；浏览器无法覆盖系统全部中断 | 用户完成后仍说不清它解决什么，或只把它叫计时器 | 让 5 人不看说明完成一次 20 秒流程，复述产品价值 |
| 回流训练 | 关系修复、游戏 respawn 和检索练习都表明“恢复能力”可被重复强化 | 日常回流受任务差异影响，趋势可能噪声很大 | 连续 7 天使用后回流延迟/主观恢复无改善，用户也不在意 | 每人记录 10 次 return latency + context recall |
| AI 生成间隙是首场景 | 高频、清晰、创始人匹配、聚集传播；AI 完成信号天然形成触发 | 模型越来越快；用户可在等待时做其他有效工作；不同 Agent 无统一完成事件 | 目标用户一周内少于 5 次明显间隙，或多数间隙不引发高刺激切换 | 5–10 人安装日志模板，记录一周等待与行为 |
| 一次回流是核心单位 | 比分钟更贴近真实损失；可测成功、延迟与上下文恢复 | 用户可能通过“确认”刷出虚假回流；第一动作难自动证明 | return count 与用户感知价值、次日使用无相关 | 只显示回流而隐藏分钟，观察用户是否仍愿意使用 |
| 回流包 / checkpoint | 2 秒准备与检索线索有研究支持；技术上 local-first 易实现 | 输入本身是摩擦；低质量 checkpoint 可能比没有更糟 | checkpoint 组回流延迟不低于对照，或 30%+ 用户跳过 | A/B：自由离开 vs 一行下一步；同任务模拟中断 |
| 注意力正向习惯循环 | 无惩罚 respawn、即时可感知的“接回”能形成内在能力反馈 | “正向上瘾”仍可能被包装成操纵；数据反馈可能诱发打卡 | 用户为了数字而非任务打开墨流，或因断档产生焦虑 | 禁用 streak/积分，只反馈一次具体回流；访谈动机 |
| 大愿景 + 窄切口 | AI Coding 能验证机制，状态模型可迁移阅读/冥想 | 过度围绕程序员文案和 adapter 会限制品牌认知 | 非程序员原型完成率或理解显著低于 AI 用户 | 用同一内核做阅读/冥想迁移原型，不改状态模型 |

## 当前判断

七项均未被“证明”，但 **AI 生成间隙 + 一行 checkpoint + 显式回流** 具有最低实验成本和最清晰因果链，足以进入 vNext。长期“训练”只作为需验证结果，不在文案中承诺。自动检测只作为 adapter 能力，不是 MVP 成立前提。
