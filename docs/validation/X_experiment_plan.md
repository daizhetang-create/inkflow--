# X｜首轮真人验证计划

## 1. 要验证的核心假设

> 高频使用 AI Web / Vibe Coding 的个人创作者会反复经历“短暂等待—离开—回来后重建上下文”；在等待前只封存一句可执行的下一步，能降低重返成本，并比再开一个高刺激页面更容易让人回到原任务。

本轮不验证“用户喜欢这套 UI 吗”，也不以专注分钟、页面停留时长或点击量证明价值。

## 2. 招募标准与人数

招募 8 人，允许 5–10 人范围内启动：

- 最近一周至少 4 天使用 Codex、Claude Code、Cursor 或其他 Web/Agent 编码工具；
- 每天至少出现 5 次 20 秒以上的 AI 等待；
- 自述等待时会打开新网页或拿起手机，且回来后偶尔忘记下一步；
- 个人创作者、独立开发者和小团队 IC 优先；
- 不以 ADHD 等医疗标签招募，不做诊断或疗效承诺；
- 排除只使用同步补全、几乎不等待 Agent 的参与者。

## 3. 使用周期与流程

周期 7 天，每人目标完成至少 12 次真实 checkpoint：

1. 第 0 天，15 分钟远程引导；观察第一次使用，不先解释 Return Gate。
2. 第 1–2 天，仅使用手动信号，建立真实基线。
3. 第 3–5 天，在真实 AI 等待中自由选择留白、远眺、伸展或一句判断。
4. 第 6 天，至少迁移一次到阅读或冥想，验证内核是否跨场景成立。
5. 第 7 天，20 分钟回访；回放最近一条真实事件序列并访谈。

研究者每天只发送一条中性提醒；参与者可开启静默模式，不设置连续签到或遗漏惩罚。

## 4. 真实使用场景

- AI 任务约 20 秒完成；
- AI 任务约 5 分钟完成；
- AI 返回失败或不完整结果；
- 用户提前回到任务；
- 用户长时间没有回来；
- 用户切走页面后再次聚焦；
- 不允许通知或浏览器不支持通知；
- 一次阅读暂停或冥想恢复；
- 低能量状态下只选择留白。

## 5. 行为数据与指标

所有数据先保留在参与者本机；研究者只在参与者明确同意后查看导出的匿名汇总，不收集 Prompt、代码、网页地址或 checkpoint 正文。

| 指标 | 事件定义 | 首轮判断线 |
| --- | --- | ---: |
| Checkpoint completion | `intention_started` 后产生 `checkpoint_saved` | ≥ 65% |
| Return Confirmed Rate | `return_prompted` 后产生 `return_confirmed` | ≥ 55% |
| Median return latency | `return_prompted` 到 `return_confirmed` | ≤ 12 秒 |
| First-step completion | `return_confirmed` 后产生 `first_step_completed` | ≥ 40% |
| Context recalled | `context_recalled=complete|partial` | ≥ 70% |
| Next-day voluntary reuse | 次日无提醒前主动创建 checkpoint | ≥ 50% 参与者 |
| 7-day repeated return | 7 日内至少 3 次完成接回 | ≥ 40% 参与者 |
| High-stimulus substitution | 自评等待时打开高刺激内容次数相较基线 | 有方向性下降 |

辅助事件包括 `wait_started`、`micro_action_selected`、`ai_completed`、`ai_failed`、`page_visibility_changed`、`session_closed`。页面隐藏只表示墨流不可见，不推断用户刷了抖音或发生漂移。

## 6. 观察记录

第一次和最后一次会话由研究者观察：

- 用户能否在 10 秒内说出产品是做什么的；
- 是否在 30 秒内完成首次 checkpoint；
- 写 checkpoint 时是否复制大段 Prompt；
- AI 完成后第一眼看哪里；
- 是否在 Return Gate 前先打开别处；
- 接回后能否直接执行那一句动作；
- 微行动是否变成新的内容消费；
- Review 是否被认为是负担。

## 7. 访谈问题

1. 你离开前脑中最后一个未完成动作是什么？
2. 等待发生前的 3 秒，你通常会做什么？
3. 这次回来后，你先看了哪里？
4. 哪句话让你不必重新拼接上下文？
5. checkpoint 哪部分像额外工作？
6. 留白或微行动有没有比刷手机更有吸引力？为什么？
7. 完成提醒在哪些时刻令人烦？
8. 如果明天没有人提醒，你会在什么场景再次打开墨流？
9. 阅读或冥想时，这个机制哪里自然，哪里勉强？
10. 你会怎样用自己的话把它讲给另一个 AI 创作者？

## 8. 三个小实验

### 实验 A｜Return 文案

- A：`回来第一步`
- B：`接回这一小步`
- 观察 checkpoint 完成率与 return latency；不使用产品停留时长定胜负。

### 实验 B｜默认恢复动作

- A：只留白
- B：看远处
- 按 20 秒与 5 分钟空档分层，观察 Return Confirmed 与主观干扰感。

### 实验 C｜低能量模式

- 仅对主动开启者减少信息和动态，不改变核心闭环。
- 观察接回率、跳过 Review 比例和“这一步太重”的访谈频率。

## 9. 失败条件

满足任一条件即视为当前机制未成立：

- 至少 20 次真实空档后，低于 8 次进入 Return Gate；
- 多数参与者认为写一句 checkpoint 比重新找上下文更费力；
- Return 提示被 50% 以上参与者描述为催促或打断；
- 用户第二天只因研究提醒使用，没有自然触发；
- 微行动显著延长离开时间，成为新的内容入口；
- 机制只能在 AI Coding 使用，阅读/冥想迁移完全不自然；
- 用户无法用一句自然语言向别人解释产品。

## 10. 继续、停止与转向规则

- **继续**：Return Confirmed ≥ 55%，且至少 4/8 人在第 7 天主动完成 3 次以上接回；下一轮才测试真实浏览器扩展 adapter。
- **削减**：checkpoint 完成率 < 65% 但接回后的 Context recalled ≥ 70%；删减输入，只保留“回来第一步”。
- **转向 Drift Rescue**：真实 AI 空档频率不足，但主动偏航救援被 5/8 人重复使用。
- **停止微行动**：它提高离开时间或被视为第二个任务；保留纯留白。
- **停止当前方向**：Return Confirmed < 40%，且质性反馈显示上下文恢复不是高频痛点。

在任何失败情况下，都不通过排行榜、签到、惩罚、AI 聊天或更多场景掩盖内核未成立。
