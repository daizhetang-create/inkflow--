# E — 迁移机制卡片库

评分为 1–5；试验成本含低/中/高。每张卡都描述实际产品行为，而非比喻。

## 01. 两秒微型 Checkpoint

- **原领域 / 场景**：航空中断准备、诊断工作中断研究；任务即将被打断。
- **真实问题**：工作记忆中的“做到哪 / 下一步”会在间隙中快速衰减。
- **用户触发**：点击“AI 开始了”或“我先离开一下”。
- **系统反应**：只问一题：“回来后第一步是什么？”允许 Enter 直接保存。
- **即时反馈**：文字被压成一条有方向的线，表示上下文已封存。
- **长期反馈**：比较有/无 checkpoint 时的回流延迟与上下文恢复率。
- **墨流体验**：用户 2–8 秒内离开墨流，不被迫填写项目表。
- **AI Coding 适配**：强；正好利用 Prompt 发出后的准备窗口。
- **阅读/冥想/工作迁移**：阅读记录“下一段从哪句继续”；冥想记录“回来先做一次呼气”；工作记录下一动作。
- **风险**：强制输入会抬高启动门槛；必须允许一键沿用上次句式。
- **试验成本 / 独特性**：低 / 5。

## 02. 回流三次握手

- **原领域 / 场景**：TCP 连接建立；双方状态可能旧或不同步。
- **真实问题**：收到“完成”通知不等于用户已重新进入任务。
- **用户触发**：AI 完成、用户主动提前回来或手动结束间隙。
- **系统反应**：系统呈现 checkpoint；用户确认/修改；完成第一动作后确认“接回”。
- **即时反馈**：间隙断线从虚线合成实线。
- **长期反馈**：记录 completion-to-prompt、prompt-to-confirm、confirm-to-first-action 三段延迟。
- **墨流体验**：核心不是通知，而是双方同步“现在继续什么”。
- **AI Coding 适配**：强；避免通知后继续刷手机。
- **阅读/冥想/工作迁移**：所有中断后都可使用。
- **风险**：熟练用户可能嫌多一步；支持“一击接回”快捷路径。
- **试验成本 / 独特性**：低 / 5。

## 03. 变化量交接（Delta Brief）

- **原领域 / 场景**：空管岗位交接；静态状态已在共享状态区。
- **真实问题**：完整复述既慢又会淹没真正变化。
- **用户触发**：等待结束时 Agent 状态或用户备注发生变化。
- **系统反应**：保留原 checkpoint，只在其旁显示“间隙变化：完成 / 失败 / 提前回来”。
- **即时反馈**：一条窄色带标出 delta，不生成长摘要。
- **长期反馈**：统计哪些变化类型最常导致回流失败。
- **墨流体验**：用户重读一行就能接管。
- **AI Coding 适配**：强；未来 adapter 可填真实状态。
- **阅读/冥想/工作迁移**：中；适合外部事件明显的场景。
- **风险**：若基线 checkpoint 不完整，delta 不能补救。
- **试验成本 / 独特性**：低 / 4。

## 04. 显式接管时刻

- **原领域 / 场景**：FEMA ICS、空管责任移交。
- **真实问题**：任务已完成、提醒已发出、用户已看到之间存在责任真空。
- **用户触发**：用户按“我接回来了”。
- **系统反应**：把 Waiting/Return 明确切到 Active，并记录时间。
- **即时反馈**：状态标签从“等你”变成“由你继续”。
- **长期反馈**：形成真实 return success，而不是通知送达率。
- **墨流体验**：一次回流成为可理解、可测量的产品单位。
- **AI Coding 适配**：强。
- **阅读/冥想/工作迁移**：强。
- **风险**：若没有随后第一动作，确认可能沦为打卡；需允许撤销。
- **试验成本 / 独特性**：低 / 5。

## 05. 下一动作箭头

- **原领域 / 场景**：任务中断的 assistant cue；并发任务中先选哪个是主要成本。
- **真实问题**：用户记得项目，却不知道回来第一步点哪里。
- **用户触发**：进入 Return。
- **系统反应**：只突出用户自己写的一个动作，五秒后其余信息才可展开。
- **即时反馈**：视觉箭头从 checkpoint 指向“接回”。
- **长期反馈**：比较用户是否修改提示、是否在 30 秒内确认上下文恢复。
- **墨流体验**：系统不替用户做决定，只把过去的决定还给他。
- **AI Coding 适配**：强。
- **阅读/冥想/工作迁移**：强。
- **风险**：过期动作会锚定用户；提供“目的变了”重算入口。
- **试验成本 / 独特性**：低 / 4。

## 06. 偏航重算，不要求原路返回

- **原领域 / 场景**：导航系统检测偏航。
- **真实问题**：分心后要求用户恢复到完美状态会增加羞耻与放弃。
- **用户触发**：点击“我飘走了”或页面重新可见后主动选择。
- **系统反应**：只问“目的还一样吗？”；若是，生成更小的当前可行动作；若否，关闭旧 session。
- **即时反馈**：原路线柔和弯向当前位置，而非亮红报错。
- **长期反馈**：记录 reroute 后是否成功回流。
- **墨流体验**：承认现实位置，保留原意图。
- **AI Coding 适配**：强。
- **阅读/冥想/工作迁移**：强。
- **风险**：不断缩小动作可能掩盖目标管理问题。
- **试验成本 / 独特性**：中 / 5。

## 07. Andon 偏航旗

- **原领域 / 场景**：精益生产中异常被人或机器立即显性化。
- **真实问题**：用户已意识到分心，却缺少一个无羞耻、立即可用的求援动作。
- **用户触发**：全局快捷按钮“我飘走了”。
- **系统反应**：停止无关动效，收缩到意图、checkpoint、接回三项。
- **即时反馈**：不是红色警报，而是一条琥珀色断点线。
- **长期反馈**：只记录成功恢复，不累计“犯错次数”排名。
- **墨流体验**：偏航被当成系统状态，不是人格失败。
- **AI Coding 适配**：强。
- **阅读/冥想/工作迁移**：强。
- **风险**：显眼入口本身可能提醒用户“你会失败”。
- **试验成本 / 独特性**：低 / 4。

## 08. 指数退避提醒

- **原领域 / 场景**：WebSocket 异常关闭后的重连退避。
- **真实问题**：连续提醒会把恢复工具变成新的打扰源。
- **用户触发**：用户忽略完成提示。
- **系统反应**：首次温和提示；未响应则延长到 2×、4×，到上限后静默。
- **即时反馈**：用户可见“稍后再提醒 / 今天别提醒”。
- **长期反馈**：学习用户可接受的提醒窗口，只存在本机。
- **墨流体验**：系统尊重未响应，而不是争夺注意力。
- **AI Coding 适配**：强。
- **阅读/冥想/工作迁移**：强。
- **风险**：浏览器后台计时和通知权限不可靠；必须有无通知降级。
- **试验成本 / 独特性**：中 / 4。

## 09. 低频心跳

- **原领域 / 场景**：WebSocket Ping/Pong 验证连接活性。
- **真实问题**：长等待时用户可能已离开，系统却假定仍在间隙。
- **用户触发**：5 分钟以上等待且用户选择允许。
- **系统反应**：一次非阻塞问题：“还在等，还是已经换了方向？”
- **即时反馈**：两个一击选项；不响应即退避。
- **长期反馈**：修正 session 状态，不制造虚假等待时长。
- **墨流体验**：心跳用于校准，不用于拉活。
- **AI Coding 适配**：中高。
- **阅读/冥想/工作迁移**：中。
- **风险**：可能成为打扰；默认关闭或仅长任务启用。
- **试验成本 / 独特性**：中 / 3。

## 10. 拉取式微行动

- **原领域 / 场景**：JIT/Kanban；下游只拉当前需要的一个单元。
- **真实问题**：微行动列表会变成新的内容流和选择负担。
- **用户触发**：进入 Waiting 后主动选择“给我一个动作”。
- **系统反应**：按估计间隙与能量只给一个：远眺、喝水、整理下一条 Prompt、留白。
- **即时反馈**：动作完成后界面退场，不继续推荐。
- **长期反馈**：本机记住用户常选与常跳过的类型。
- **墨流体验**：没有无限滑动，没有奖励币。
- **AI Coding 适配**：强。
- **阅读/冥想/工作迁移**：强。
- **风险**：内容推荐容易变成“微型 TikTok”；必须单次单项、无 feed。
- **试验成本 / 独特性**：低 / 4。

## 11. 留白也是完成

- **原领域 / 场景**：生态恢复；移除压力，让系统自我恢复。
- **真实问题**：休息 App 常把恢复变成另一项任务。
- **用户触发**：选择“什么都不做”。
- **系统反应**：隐藏文本和计时大数字，只保留完成信号与退出。
- **即时反馈**：环境安静下来，不要求呼吸跟拍。
- **长期反馈**：只询问留白是否帮助回流，不奖励时长。
- **墨流体验**：系统有能力不占据用户。
- **AI Coding 适配**：强。
- **阅读/冥想/工作迁移**：强。
- **风险**：没有边界会转成无意识漂移；需温和完成信号。
- **试验成本 / 独特性**：低 / 4。

## 12. 预站位窗口

- **原领域 / 场景**：F1 进站前角色和工具提前到位。
- **真实问题**：AI 完成后才找文件、回忆标准、构思下一 Prompt，错过最短回流窗。
- **用户触发**：开始等待。
- **系统反应**：把 checkpoint 转成桌面可见的“回来台”，可选复制下一步。
- **即时反馈**：一条待接回轨道停在屏幕边缘。
- **长期反馈**：评估准备动作是否降低回流延迟。
- **墨流体验**：等待不是空白，而是为回流站位。
- **AI Coding 适配**：强。
- **阅读/冥想/工作迁移**：中高。
- **风险**：浏览器无法真正置顶；第一版只做页面/标题/通知降级。
- **试验成本 / 独特性**：中 / 5。

## 13. 人类放行

- **原领域 / 场景**：F1 出站灯由高级技师最终 go/no-go。
- **真实问题**：标题变化或定时模拟可能误判 AI 已完成。
- **用户触发**：系统提示“可能完成”后用户确认。
- **系统反应**：明确显示检测来源：手动、计时模拟、页面可见性或 adapter。
- **即时反馈**：只有用户确认后才进入 Return。
- **长期反馈**：记录每种来源的准确率，为未来集成决策提供证据。
- **墨流体验**：不伪装 AI 集成。
- **AI Coding 适配**：强。
- **阅读/冥想/工作迁移**：中。
- **风险**：自动化感降低，但换来信任。
- **试验成本 / 独特性**：低 / 4。

## 14. Sign-in / Time-out / Sign-out 三点核对

- **原领域 / 场景**：WHO 手术安全清单。
- **真实问题**：高风险信息常在开始、执行中与交付时分别遗漏。
- **用户触发**：发出 Agent 任务、等待中改变方向、收到结果。
- **系统反应**：三处分别只核对“目的”“是否仍等同一件事”“下一步”。
- **即时反馈**：状态轨道显示当前是哪一个转换点。
- **长期反馈**：分析问题发生在哪个转换点，不只看最终成功。
- **墨流体验**：每个核对不超过一句，不复制 19 项清单。
- **AI Coding 适配**：强。
- **阅读/冥想/工作迁移**：中高。
- **风险**：医疗隐喻过重；产品文案不使用“安全检查”。
- **试验成本 / 独特性**：低 / 4。

## 15. Return Packet

- **原领域 / 场景**：Flink 一致性 checkpoint + FEMA 事件简报。
- **真实问题**：刷新、离线或多标签页会让内存状态丢失。
- **用户触发**：每次 checkpoint_saved。
- **系统反应**：版本化保存最小字段：intent、lastAction、nextAction、mode、timestamps、source。
- **即时反馈**：刷新后直接显示“继续这一条”，不丢当前会话。
- **长期反馈**：只保留用户选择的最近节律与匿名本机事件。
- **墨流体验**：技术故障不等于认知断裂。
- **AI Coding 适配**：强。
- **阅读/冥想/工作迁移**：强。
- **风险**：工作上下文敏感；禁止自动保存 Prompt/代码正文，提供清空。
- **试验成本 / 独特性**：中 / 5。

## 16. 稳定任务身份

- **原领域 / 场景**：Flink operator UID 与 savepoint 恢复。
- **真实问题**：标题相似或界面升级后，旧 checkpoint 无法可靠归属。
- **用户触发**：创建注意力去向。
- **系统反应**：生成稳定 `taskId/sessionId/schemaVersion`，展示人类标题但不以标题作主键。
- **即时反馈**：用户无感；多标签页冲突时只保留最新版本。
- **长期反馈**：支持数据迁移与未来跨设备 adapter。
- **墨流体验**：底层可靠，不暴露工程术语。
- **AI Coding 适配**：强。
- **阅读/冥想/工作迁移**：强。
- **风险**：实现不可过度工程化。
- **试验成本 / 独特性**：中 / 3。

## 17. 轻量检索挑战

- **原领域 / 场景**：记忆提取练习；尝试回忆比直接重读更利于未来提取。
- **真实问题**：用户看到长摘要会误以为“熟悉”等于“恢复”。
- **用户触发**：Return 开始。
- **系统反应**：先给 3 秒自我回忆：“下一步是什么？”再允许揭示 checkpoint；可关闭。
- **即时反馈**：用户选择“想起来了 / 给我线索”。
- **长期反馈**：自评 context_recalled，而不是测试分数。
- **墨流体验**：把回流本身训练成能力。
- **AI Coding 适配**：中高。
- **阅读/冥想/工作迁移**：强。
- **风险**：疲劳时像考试；低能量模式直接展示线索。
- **试验成本 / 独特性**：低 / 5。

## 18. 回流缓坡

- **原领域 / 场景**：睡眠惯性；完整认知性能在状态切换后渐进恢复。
- **真实问题**：完成提醒后立即要求读完整结果、做高风险判断会失败。
- **用户触发**：从长等待、恢复或明显偏航回来。
- **系统反应**：第一动作优先低负荷：看目标、读最后一句、打开文件；随后才显示完整工作。
- **即时反馈**：界面信息密度在 5–15 秒内随用户动作展开。
- **长期反馈**：低能量模式的回流成功率与延迟。
- **墨流体验**：不是“赶紧回来”，而是“先接住，再加速”。
- **AI Coding 适配**：强。
- **阅读/冥想/工作迁移**：强。
- **风险**：动效延迟不能阻止用户直接继续。
- **试验成本 / 独特性**：中 / 5。

## 19. 无惩罚 Respawn

- **原领域 / 场景**：游戏失败后的存档点与脚手架；关系修复而非零冲突。
- **真实问题**：一次错过提醒容易让用户放弃整天或隐瞒失败。
- **用户触发**：长时间未回、关闭页面后重开、主动选择“这次没接住”。
- **系统反应**：直接回到最近 checkpoint，给更小下一步；不扣分、不破 streak。
- **即时反馈**：显示“从这里继续”，不显示“失败 1 次”。
- **长期反馈**：只展示“你已回来多少次”与个人延迟趋势，不做排行榜。
- **墨流体验**：正向上瘾对象是回来，不是保持完美。
- **AI Coding 适配**：强。
- **阅读/冥想/工作迁移**：强。
- **风险**：视觉奖励过强会变成操纵；保持克制。
- **试验成本 / 独特性**：低 / 5。

## 20. 冷却后的最小复盘

- **原领域 / 场景**：关系冲突恢复、医疗 Debrief、体育恢复监测。
- **真实问题**：刚回到任务就要求复盘会再次打断；完全不复盘又无法学习节律。
- **用户触发**：完成第一动作后或 session 结束时。
- **系统反应**：只问一题：“上下文回来了吗？”选项：完整 / 一部分 / 没回来；可跳过。
- **即时反馈**：一行非评判性总结，例如“这次 18 秒接回”。
- **长期反馈**：本机形成推荐：何种 checkpoint、间隙动作和提醒更适合用户。
- **墨流体验**：反馈用于变得更会回来，不用于展示生产力身份。
- **AI Coding 适配**：强。
- **阅读/冥想/工作迁移**：强。
- **风险**：频繁询问会烦；按采样率出现并允许关闭。
- **试验成本 / 独特性**：低 / 4。

## 初筛结论

进入产品内核候选的组合是：**两秒微型 Checkpoint + 回流三次握手 + 下一动作箭头 + 无惩罚 Respawn**。它们形成完整因果链，并且即使删除计时、声景、账号、统计和开场仍然成立。预站位、退避提醒、Return Packet 与低能量缓坡进入系统层；其余机制保留为实验模块，避免 MVP 重新膨胀。
