# C — 失败诊断

## 起步错在哪里

我们从“做一个阅读专注 App”这个既有品类出发，再寻找差异化包装；正确顺序应当是先发现 AI 协作造成的新型中断，再发明一个旧工具无法完成的恢复动作。旧版优化的是专注时长，创始人的真实损失却发生在等待 AI 后丢失上下文、拿起手机以及重新进入任务的成本。

## 为什么阅读专注工具不是上位定义

阅读、冥想、工作和 AI Coding 的共同问题不是需要同一个计时器，而是人在状态切换、等待、偏航后失去原本的注意力去向。阅读只是其中一个情境；用阅读定义产品会把数据限定为书名、页数和分钟，把机制限定为“留在原地”。

## 为什么加开场、动画、声景、统计仍无产品价值

这些元素改变感受，不改变因果链：用户仍先选时长，系统仍只倒计时，结束仍只累计分钟。它们不保存上下文，不桥接 AI 等待，不降低回到任务的第一步成本，也不训练恢复能力。12 秒开场甚至推迟了第一次价值。

## 为什么 UI 没有表现核心机制

旧版没有核心机制可表现。大圆环在视觉上宣告“时间是中心”，右侧卡片宣告“功能很多”，七日统计宣告“累计越多越好”。没有 checkpoint 的压缩、间隙的状态转换、完成信号、回流门或上下文重新浮现，因此 UI 只能表现番茄钟。

## 为什么不会形成长期依赖或主动传播

- 替代成本近乎为零：系统计时器、Forest、浏览器扩展都能完成主要任务。
- 记录不能在下一次行动中产生价值，只回馈历史数字。
- 建议不可解释也不个性化，几次使用后就能看穿规则集合。
- 产品没有一个可讲述的“瞬间”；用户只能说“它是一个好看的阅读计时器”。
- 开场与品牌越精致，越放大核心体验普通的落差。

## 为什么它不属于 AI 时代

旧版既不感知人机协作状态，也不支持 Agent 间隙，不保存下一步，不处理异步完成，不测量回流延迟。增加 AI 文案或聊天框也不会改变这一点。AI 时代的独特性必须来自异步协作产生的新状态机，而不是模型标签。

## 问题分层

### 产品问题

- 北极星是分钟，而不是成功回流与上下文恢复。
- 第一用户、第一场景和不可删除动作都不清楚。
- 功能彼此并列，没有自增强循环。
- 产品要求用户停留，未帮助用户尽快离开产品回到真实任务。

### 视觉问题

- 卡片、圆环、侧栏、统计是通用效率产品语法。
- 暖纸/墨绿/书本圆环把品牌锁在阅读和茶室式安静。
- 大量装饰动效表达“氛围”，没有表达等待、偏航、重连和恢复。

### 技术问题

- 单体组件与布尔状态组合难以验证异常流程。
- 无事件模型、持久化版本、多标签页协调和离开/返回处理。
- 无真实 Agent adapter；规则建议却使用近似智能的措辞。
- 测试验证字符串与文件存在，未验证用户行为和状态转换。

## 可执行重构原则

1. 把成功单位从“完成 X 分钟”改为“带着上下文完成一次返回”。
2. 用显式状态机统一工作、等待、偏航、回流、恢复和轻复盘。
3. 首屏只保留注意力去向与一个最小 checkpoint，不先展示统计/设置。
4. 手动模式必须完整可靠；所有自动检测明确标注能力边界。
5. 视觉只为状态转换服务，signature interaction 必须让下一步从间隙中重新出现。
